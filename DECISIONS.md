Environment & Toolchain Friction: Documented Node.js version incompatibility (v20.6.1 vs create-vite@9 requiring styleText in node:util) and resolved it by pinning create-vite@5 to maintain stability without breaking existing local environments.
Data Modeling Evolution (1:N $\rightarrow$ M:N): Initially modeled coils with a single foreign key (fitsDevice: 'dev-1'), which caused data duplication across shared pod ecosystems. Refactored to a many-to-many array mapping (fitsDevices: [...]) and implemented reverse-lookup queries to surface cross-compatible stock on the shelf.
Domain Safety Guardrails: Separated physical fitment from electrical compatibility—e.g., an XROS 0.6Ω pod physically clicks into an XROS Mini (16W), so the UI still displays it as a physical match, while dynamically flagging an electrical under-power warning (minW > maxWattage).
Point-of-Sale Ergonomics: Replaced static button grids with real-time case-insensitive filtering (useState + .includes()) and one-tap clear actions to minimize till friction during peak retail hours.
- **Compatibility Engine Extraction & $O(1)$ Lookup Optimization:** Refactored business logic out of `App.jsx` into a pure utility module (`src/utils/compatibility.js`) with defensive null guards. Pre-indexed device IDs into a JavaScript `Map` (`deviceNameMap`) to resolve cross-compatible hardware names in $O(1)$ time per lookup rather than running nested `.filter()` scans inside the render loop, alongside memoizing filtered lists with `useMemo` and adding ARIA attributes (`aria-pressed`, `role="alert"`) for keyboard and screen-reader accessibility.
